# 账号安全与操作记录

## 我的账号

后台 `/admin/account` 提供账号资料、密码修改、有效登录列表、退出指定登录、退出其他全部登录及退出当前登录。

密码修改要求旧密码、新密码及前端确认；新密码 12–128 个字符且不能与旧密码相同。Core 使用现有 Better Auth 校验旧密码、计算哈希并撤销已有会话，随后清理认证库创建的替换会话并写安全记录。不会把替换令牌或 Cookie 返回调用方。成功后包括当前登录在内的全部登录失效，网站返回登录页，APP 也须重新登录。密码仅在本次请求中处理，不写入操作记录；不可通过管理员接口直接改别人的密码。

每位用户的密码操作限 5 次/15 分钟，参数错误及密码错误同样计数。会话查询限 120 次/分钟，会话退出限 30 次/分钟。内部认证会话须满足认证库的敏感操作新鲜度要求；过期时需重新登录。

会话列表只查询当前用户，过滤过期会话，每次读取最多 21 条并展示 20 条，主键游标分页；不返回令牌。设备描述来自客户端，不能用作认证依据；IP 为空时展示“未记录”，默认不信任转发 IP。退出指定会话在 DELETE 中同时限定 userId，不允许操作他人会话，也不能用该操作退出当前会话；当前登录使用原有 sign-out。批量退出其他会话始终保留当前会话。

## HTTP 契约

网站页面读取直接调用 Core，网站写入及 APP 通过同一服务的 HTTP 适配器，不维护另一套业务规则。所有写入校验来源、使用 JSON 严格字段契约，实际读取上限 4 KiB。

- `GET /api/v1/account/sessions?before=...`：仅自己的有效会话，游标为空时省略 before。
- `POST /api/v1/account/sessions/revoke`：`{"scope":"session","id":"..."}` 或 `{"scope":"others"}`，返回 `{"revoked":数量}`。
- `POST /api/v1/account/password`：`{"currentPassword":"...","newPassword":"..."}`，成功返回 `{"reauthenticate":true}`。

账号服务允许普通用户管理自己的安全信息，后台页面仍只允许管理员。Cookie 写入须匹配站点 Origin；无 Cookie 的原生 APP 支持 Bearer。所有响应 no-store。契约位于 `packages/extension-api/account`，已加入 OpenAPI。

## 操作记录

`/admin/audit` 按站点设置、用户管理、账号安全分类；切换分类会重置分页。分类分别调用一次有上限的查询，无跨类别全表聚合、总数扫描或逐行查询。每类最多读取 31 条、展示 30 条，使用各自主键游标。

- 设置记录沿用 `GET /api/v1/admin/audit`。
- 用户状态/权限记录使用 `GET /api/v1/admin/audit/users`，显示操作者、目标用户和变更字段，隐藏原始 before/after 及禁用原因正文。
- 账号安全记录使用 `GET /api/v1/admin/audit/account`，显示修改密码、退出指定登录或退出其他登录等成功操作；不记录密码、令牌。密码变更的 affectedSessions 仅是最终清理的替换会话数，不作为原会话总数展示。

记录只读，仅管理员可读。写权限变更和会话退出的记录与对应数据库操作同一事务提交。密码变更沿用认证库事务，随后单独进行会话清理与记录提交，不承诺跨两步的整体原子性；若第二步失败，API 返回错误，原有会话已失效，新密码可能已生效，应重新登录确认。

新增迁移 `004_account_security.sql`，保留已应用迁移与现有数据。`pnpm test:security` 在独立临时库验证归属保护、分页与脱敏、来源和字段校验、密码修改、全部会话撤销、尝试次数限制及三类审计。

## 页面异常

App Router 共享布局会保留，因此每个受保护页面的读取也处理 401/403。登录过期或权限变化时进入重新登录页；其他异常显示重试入口，不把所有错误归因为数据库。读写服务仍各自鉴权，页面跳转不代替权限校验。
