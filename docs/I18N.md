# 前台界面语言

前台使用 next-intl 4.14.9，支持 `zh-CN` 和 `en`。设置菜单的语言选择保存 `sohoin-locale` Cookie（有效期一年、Path=/、SameSite=Lax，HTTPS 下加 Secure），随后通过 Next 的 `router.refresh()` 更新服务端和客户端界面，不改变路径、查询参数或锚点。

语言优先级：有效 Cookie → 浏览器 Accept-Language 中优先级最高的受支持语言 → 简体中文。中文地区标签统一对应简体中文，英语地区标签对应 English；未支持的值不能作为文件路径使用。Cookie 只表示公开的界面偏好，不参与登录或授权。

## 文案边界

- `apps/web/i18n/messages/zh-CN.json` 与 `en.json` 分别维护中文和英文；`Web` 是前台文案，`UI` 是共享交互组件的文案。
- 服务端页面继续服务端渲染，用 `getTranslations`；同步组件用 `useTranslations`。前台布局提供所选语言，根布局为后台共享组件提供中文默认文案。
- 帖子、评论、标题、昵称、个人介绍、站点设置、分区名称、管理员配置的表情名称及图片替代文本保留原文。站名继续来自 settingsService.readPublic。
- 后台业务页面不接入翻译，维持中文；后台容器显式声明 `lang="zh-CN"`。前台文档语言由服务端输出。
- 相对时间随界面语言变化；日期仍以 Asia/Shanghai 显示，并标明时区，不改动原始时间戳。
- 语言切换不重置发帖草稿；已经通过服务端动作追加的回复视图会重置到当前页初始回复，避免保留旧语言的服务端节点。

## URL 与搜索

没有语言路由、重定向或重复语言页面，原 canonical、分页和 sitemap 保持原有地址。仅翻译界面标题和无内容时的备用文案，不翻译真实内容的 metadata 或 JSON-LD。此方案不添加指向同一 URL 的虚假语言版本 hreflang。

## 待执行验收

本次只完成源码接入和静态审阅，未执行构建、类型检查、测试或浏览器验收。按项目约定由用户执行：

```powershell
pnpm typecheck
pnpm build
node --import=tsx --test apps/web/i18n/locale.test.ts packages/ui/tests/relative-time.test.ts
pnpm test:security
```

`pnpm test:security` 会创建专用测试数据库。浏览器重点检查：首次访问的语言协商；中英文切换后刷新和新标签页记忆；详情、分页、图片预览和错误提示；英文在窄屏下的布局；帖子评论原文；中文后台。生产部署不得把带 Cookie 的个性化 HTML 作为所有访客共用的静态缓存。

安装未启用 next-intl 的实验性文案提取/预编译功能；间接依赖 `@parcel/watcher` 与 `@swc/core` 的安装脚本未授权执行，并在 pnpm allowBuilds 中明确禁用。
