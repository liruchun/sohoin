# 数据完整性、文件清理与备份恢复

这些是操作员手动维护命令，本轮没有建立定时任务、后台恢复按钮或前台功能，没有新增 npm 依赖。

## 数据约束

009 为追加迁移：内容作者外键使用 `ON DELETE RESTRICT`，有文章的作者不能被直接物理删除；现有禁用账号功能不受影响。作者注销、匿名化和转移规则仍待产品讨论。审计中的历史账号标识不补强制外键，以保留历史记录。

同时补上内容类型/标题/摘要/正文长度、分类标签名称/slug/说明长度、非负版本、发布时刻、设置 JSON 对象形态、正限流计数及非负会话影响数。迁移遇到不合法旧数据会整体失败，不截断、不删除、不自动改写数据。

`pnpm db:check` 只读检查孤立作者、主要内容字段、分类标签格式和非 ready 媒体引用，输出数量而不输出用户正文。它是日常检查入口，不替代 PostgreSQL 外键/CHECK、Core 参数校验或完整文件校验。

## 文件清理

```text
pnpm media:cleanup
pnpm media:cleanup --apply
pnpm media:cleanup --apply --grace-hours=48 --limit=1000
```

默认只预览候选文件；`--apply` 才实际删除。宽限期默认 48 小时，最低允许 24 小时。每次最多处理 1,000 个候选文件，可设 1–10,000。

清理规则：

- 已软删除的媒体且没有内容引用：重试清理其实际文件；保留元数据、对象键和审计记录。
- 在资源表、派生文件表都没有记录，且修改时间超过宽限期的文件：视为上传中断遗留文件。
- 未引用但 ready 的图片、pending/failed 等仍有记录的图片和较新的无记录文件：保留。
- 只处理 `images-v1/年/月/随机标识[-thumb].webp|png|jpg`，不处理任意文件名，不递归跟随符号链接或目录联接。文件路径重新验证在配置根目录内，逐个 unlink，不递归删除媒体目录。

文件遍历按目录流式读取，数据库每批查询 100 个对象键，最多保留 20 条样例报告，避免逐文件查询与一次载入整个目录。候选数量有界，扫描本身可能遍历整个媒体目录，适合低峰维护窗口；大规模站点后续再接可续跑后台任务。`failed` 非零时命令失败退出。

## 数据库与文件一致性

上传和删除在物理文件操作前获取 PostgreSQL 共享会话维护锁；清理和备份取同一把独占锁。锁繁忙时媒体写入返回 503 和 `Retry-After: 5`，不接收/处理上传内容；正常读取不受此锁限制。操作员命令也快速失败并提示重试，避免挂起请求。连接关闭后 PostgreSQL 自动释放会话锁。

备份还持有迁移锁，防止期间改表。数据库使用只读可重复读事务导出快照，并通过 `pg_dump --snapshot` 使用同一快照；业务行数和迁移校验记录也来自该快照。媒体文件在独占锁内复制，文件清单通过数据库游标每批取 500 行。普通内容/设置写入可以继续，备份仍对应同一个数据库快照。不要在维护期间用绕过这些服务的手工 SQL 或其他程序修改媒体记录和文件。

PostgreSQL 工具及快照行为参考官方 [pg_dump 文档](https://www.postgresql.org/docs/17/app-pgdump.html) 和 [pg_restore 文档](https://www.postgresql.org/docs/17/app-pgrestore.html)。

## 准备外部工具

本机已获授权，从 PostgreSQL [Windows 下载页面](https://www.postgresql.org/download/windows/) 指向的 EDB zip 分发包补充 `pg_dump`、`pg_restore` 和所需 DLL，当前版本 17.11。没有安装新服务或替换项目正在运行的 PostgreSQL。工具放在 `.local/tools/postgresql17`，不是项目依赖。

环境配置，均为服务端变量：

```text
MEDIA_STORAGE_DIR=D:/project/sohoin/.local/media
PG_BIN_DIR=D:/project/sohoin/.local/tools/postgresql17
BACKUP_DIR=D:/project/sohoin/.local/backups
```

其他机器需另外准备相容的 PostgreSQL 客户端工具并设置绝对路径。连接凭据从环境传给子进程，不拼接进命令文本或备份清单。

## 创建备份

```text
pnpm site:backup
```

每次创建新的目录：`database.dump`（custom 格式）、`media/`、流式 `files.jsonl`、`manifest.json`。清单记录文件体积/SHA-256、备份校验值、主要业务表行数及迁移校验值。源文件缺失、体积不符、工具失败或不支持的存储提供商会使备份失败。未完成目录保留 `.partial` 后缀，完成后才改名；恢复工具拒绝 `.partial`。

备份只复制数据库中 ready 的本机资源和 ready 派生文件，不复制已删除资源和无记录遗留文件。备份目录必须独立于媒体目录。命令不自动清除历史备份，也没有异地复制或加密；本机备份不等于磁盘损坏后的灾备。备份内含账号密码哈希和站点数据，目录应限制访问并按部署方案加密/异地保存。

此备份覆盖数据库与媒体，不包含应用源码、Custom 源码或 `.env.local`。源码版本与环境配置须另行安全保管，恢复时使用相容的 Core/Custom 版本，不要把环境密钥写入普通文档。

## 恢复到新目标

先私下配置 `RESTORE_DATABASE_URL` 和 `RESTORE_MEDIA_DIR`，再执行：

```text
pnpm site:restore D:/project/sohoin/.local/backups/完整备份目录名
```

- 目标数据库名必须以 `sohoin_restore_` 开头，且不存在；目标媒体目录也必须不存在，并与当前媒体目录和备份目录分离。
- 不提供覆盖当前数据库、`--clean`、删库恢复或自动切换站点的模式。
- 创建目标前验证备份和每个媒体文件的 SHA-256、大小、路径、数量；不跟随媒体符号链接。SHA-256 用于完整性校验，不是来源签名，只恢复可信备份。
- `pg_restore --single-transaction --exit-on-error` 恢复数据库，再核对主要业务表行数、迁移记录及复制后的文件哈希。
- 成功后清空恢复库中的 session、verification 和 request_limits，避免旧会话及重置令牌复活；账号和内容不被删除。
- 失败时保留新目标供检查，不会删除或覆盖当前站点。确认恢复结果后再另行进行上线切换。

## 已验证

`pnpm test:maintenance` 使用专用临时数据库和媒体目录，实际调用 pg_dump/pg_restore，覆盖数据库约束、作者删除保护、维护锁、清理预览与执行、正常文件保护、路径越界拒绝、业务记录/媒体关联/实际图片恢复、旧会话清除、拒绝覆盖和篡改校验。测试完成移除自己创建的恢复库与目录，保留正式数据。

上线前仍需确定备份频率、保留周期、异地位置、密钥管理、恢复目标时间及真实数据规模下的维护时长。
