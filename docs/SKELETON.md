# 公共骨架加载与页面过渡

当前契约：2026-10-19。本文件描述当前实现，替代此前串行停留、交接分段及各页面独立计时的说明。适用于公开前台，不向后台引入前台动画。

## 统一入口

- 首次打开或刷新任意公开页面：唯一常驻 Splash → 真实内容测量生成骨架 → 公共显字流程。首次文档不输出两条 SPA 短占位替代完整正文高度，以保留浏览器滚动恢复。
- SPA 已有完整可用数据：直接显示，不补播骨架、不强行等待。判断依据是实际可用内容和是否提交过等待分支，不是是否曾访问 URL。
- SPA 需要异步数据：两条占位骨架 → 数据到达后测量真实布局 → 实测骨架接管 → 公共显字流程。摘要或 bodyTruncated 内容不能被当作完整详情正文。
- 首屏与 SPA 都由 packages/ui 的同一个 sequence 控制显字。页面只提供内容、占位和骨架标记，不自行计时。

评论区域额外启用`revealToken`：由服务端的DiscussionContent为每份响应传入一个对象。首次展示该响应即使取数很快也走真实骨架渐显；同一份Next路由缓存再次进入直接显示；重新请求取得新对象后重新渐显。顶层SkeletonBoundary通过WeakSet共享已完成展示的响应身份，不存评论、URL或缓存有效期，也不强引用响应。不使用客户端每次render创建的对象作为标记。未完成就离开不会记为已展示。该标记用于拦截详情的评论及顶层评论的客户端“加载更多”；首屏ContentPage不接入，普通未标记区域仍沿用实际等待判定。

顶层评论的客户端“加载更多”在评论区内部新建独立的 `SkeletonBoundary`/`SkeletonContent`，以本次请求的 token 作为 `revealToken`：点击后先显示一条讨论占位，数据到达后按同一流程测量、展开并逐条渐显；根评论下的“展开更多回复”使用同一批次机制和单条回复占位骨架。首屏与拦截详情的初始评论等待仍保留两条占位。显字完成后，新条目合并回原 `<ol>`，临时批次容器卸载；两者都不写 URL，也不触发行级页面过渡。批次骨架开启 preserve-all，不按视口裁掉已加载条目，最多按批次上限生成骨架行，避免只显示一条占位、其余真实内容留在隐藏高度里。两个按钮触发的批次都先让占位完成一次绘制再发起请求，快速响应也必须经过占位→实测骨架→渐显，不能直接替换占位造成高度跳变。

通用首屏入场标记：

- `data-skeleton-chrome-group=""`：声明独立排序容器，不动画容器本身。
- `data-skeleton-chrome-item=""`：容器内参与入场的元素，可以隔着布局节点；按DOM阅读顺序自动排序。未标记的元素不参与，也不占延迟位置。
- `data-skeleton-chrome=""`：保留单个外壳整体入场，用于页脚等；同一节点不要与分组/子项标记混用。
- 容器CSS定义`--skeleton-enter-transform`、`--skeleton-enter-duration`、`--skeleton-enter-stagger`、`--skeleton-enter-ease`，子项继承。现有侧栏和顶部菜单已定义这些变量，新元素只加子项标记即可。
- 隐藏到无尺寸的元素不参与、不占序号；嵌套分组各自排序，已标记元素内部的子项不再重复动画。超长分组延迟上限1200ms，尾部元素可同时入场，避免新增内容无限拉长首屏等待。

```tsx
<aside data-skeleton-chrome-group="" className={styles.sidebar}>
  <section data-skeleton-chrome-item="">第一个模块</section>
  <section data-skeleton-chrome-item="">后续新增模块</section>
</aside>
```

## 页面进退动画

2026-10-21 改为 React 19.3.1 的 `<ViewTransition>`。按本地 Next 16.4.1 随包文档，App Router 无需额外配置。ReadingLink 直接传递 Next Link 的 transitionTypes，卡片通过 router.push 的同名选项传递方向；Next 保留预取、修饰键、新标签页、锚点、路由、历史与滚动职责。

PageTransition 是常驻正文边界，使用 update 而非 enter/exit 响应 detail-forward/detail-back；提交时机由 React 管理；正文边界按 pathname 与查询参数生成唯一快照名称，让旧列表与新详情各自保留捕获时的滚动坐标与尺寸，不共享几何位置。不改变 React key、不重挂背景列表。Header、侧栏和分割线继续保持静止快照。信息流标签用 feed-forward/feed-back，仅激活 FeedFrame 的列表边界。默认 none，未携带类型的刷新、历史遍历与独立内容更新不播放方向快照。位移与时长遵循 DESIGN.md；不再自建路由提交 Promise、超时或快照取消/清理。

返回按钮及 Escape 仍调用 router.back，不监听 popstate、不维护历史方向表。当前框架的历史遍历可能同步提交而不触发 React ViewTransition；保留的背景列表在首次被详情覆盖后，通过 @starting-style 从左侧入场，无透明度变化。浏览器前进恢复拦截详情时，详情 document 表面通过 @starting-style 从右侧 3.125rem 淡入，使用现有 page-enter 时长与 emphasis 曲线；首次挂载或从隐藏恢复显示时生效，普通已显示内容更新不重播。首屏列表及直达详情不触发这套补偿；React 快照进行中关闭 CSS 入场，并将真实详情保持在最终位置和透明度，避免重复位移。两种补偿都只有目标页面入场，不提供旧页面退出动画，其他页面之间的历史遍历也不保证有动画。

系统与站内减少动态效果均禁用方向动画。图片灯箱保留独立原生图片过渡，页面边界只响应导航类型，不主动为灯箱状态更新生成正文动画；快速导航、灯箱与导航交叉发生时仍需实测。骨架阶段及数据等待保持原机制，不由页面过渡控制。

迁移后用户反馈深滚动列表进入详情时先跳顶再切换。源码核对发现，常驻边界的同名快照组配合 animation:none，会让旧快照使用新页面几何位置；现改为不同路由独立名称，并移除快照的强制高度与裁切尺寸。保留 Next 默认滚动，不用 scroll:false、scrollTo 或延时补偿。此修正尚未浏览器确认。

## 布局、恢复与清理

普通滚轮、拖动滚动条、指针、键盘（包括Ctrl）、触摸及焦点不会跳过骨架。启动时也不再因内容内部有焦点而跳过。

布局变化不能作为普通提前显字出口。SSR在入场阶段可有界更新测量；SPA展开中的宽度变化只标记布局需要更新，在几何完成后恢复自然尺寸、批量重测并绘制最终骨架，再交接正文。保留异常、减少动态效果、页面隐藏和卸载的恢复/清理；测量或动画异常不永久遮住正文。

## 内容标记与测量边界

- 正文仍由服务端渲染；卡片使用data-skeleton-item，文字等区域使用data-skeleton-part，媒体用block，头像用circle。操作容器用actions，其可见控件用data-skeleton-shape；单个占位控件用action。
