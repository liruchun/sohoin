# 表情回应与私密收藏

追加迁移 `012_interactions.sql` 已应用。文章/帖子表情、评论表情、内容收藏和评论收藏的数据表、Core 服务、HTTP 接口与 OpenAPI 已实现。未新增依赖，未修改 Custom，暂不提供前台按钮、收藏页或新增后台配置页面。

## 数据与规则

`content_reactions`、`comment_reactions` 分别通过真实外键关联内容或评论，并关联用户及表情目录。复合主键限制每个用户对每个对象仅保留一个表情；选择其他表情会替换，设置 null 取消。重复设置同一个表情不会更新记录。

`content_bookmarks`、`comment_bookmarks` 使用用户与对象的唯一约束防重复，另有用户与收藏编号索引用于倒序游标分页；对象索引用于外键级联清理。重复收藏不改变原收藏顺序，取消后重新收藏获得新编号。当前不实现收藏夹。

`reaction_types` 保存稳定编码、标签、表情字符、启用状态、排序和版本。初始目录：like 👍、love ❤️、laugh 😂、wow 😮、sad 😢。管理员目前可通过接口启停及排序；版本冲突返回 409，变更写入设置操作记录。停用不删除历史表情记录或计数；目录仍返回该类型供展示历史，选项应只使用 enabled=true 的类型。增加新编码及修改字形/标签暂通过后续迁移，不开放任意代码或文件上传。

收藏保持私密。接口只使用登录会话中的用户身份，不接受传入 userId，不公开收藏人数、收藏用户或其他人的收藏列表。

新增表情/收藏要求账号有效、内容已发布。评论还要求自身正常、整串未隐藏；单独隐藏一级评论不隐藏其二级回复，一级正文已删除也不阻止仍正常的二级回复接收互动。取消自己原有的表情/收藏不要求对象仍可见，且对不存在的记录幂等返回成功。隐藏内容的收藏暂不展示，恢复可见后重新展示；永久删除所属内容或用户时，由外键清理记录。评论软删除保留关联记录但不展示或接受新增。

写入事务锁定有效用户与表情配置，再按所属内容、一级评论、目标评论顺序取得共享锁并重新检查可见性，与下架、隐藏、删除及禁用账号操作串行协调，防止在旧可见状态下写入。事务内固定表名，所有请求值参数化。

## 共用服务与接口

Core 导出 `setReaction`、`setBookmark`、`getInteractionBatch`、`getOwnBookmarks`、`getReactionTypes`、`getAdminReactionTypes`、`updateReactionType`。网站服务端和 Custom 通过 Core 共用服务调用；未来 APP 走薄 HTTP 适配层，不维护另一套业务逻辑。

| 方法及路径 | 用途 |
| --- | --- |
| GET `/api/v1/reaction-types` | 公开目录，包含 enabled 状态，不含配置版本 |
| GET `/api/v1/admin/reaction-types` | 管理员读取目录及配置版本 |
| PATCH `/api/v1/admin/reaction-types/{code}` | `{version, enabled, position}` 修改启用及排序 |
| PUT `/api/v1/interactions/{kind}/{id}/reaction` | `{code:"like"}` 设置/切换；`{code:null}` 取消 |
| PUT `/api/v1/interactions/{kind}/{id}/bookmark` | `{active:true}` 收藏；false 取消 |
| POST `/api/v1/interactions/{kind}/summary` | `{ids:["1","2"]}` 批量读取表情数量和自己的互动状态 |
| GET `/api/v1/account/bookmarks/{kind}?before=...` | 当前用户的收藏，游标分页 |

kind 只允许 `content`（文章/帖子）或 `comments`。除公开目录外，上述读取与写入均需要登录，配置管理额外要求管理员。当前批量摘要含个人状态，因此暂不支持访客读取；访客计数需求应在前台阶段单独接入，不可通过伪造用户身份调用。

批量摘要最多 30 个不同编号，不可见对象省略。返回每个对象的 `reactions`、`myReaction` 和 `bookmarked`，不返回正文、其他用户身份或私密收藏统计。收藏每页最多 30 条，内部读取 31 条判定下一页，不查询总数、不加载全文。响应 no-store；PUT/PATCH/POST 校验来源和 JSON 请求体大小，参数使用严格白名单，Core 内执行共享限流。

## 性能与验证

列表互动通过一次批量查询读取所需对象的计数及当前用户状态，不逐条发请求或查询。表情计数目前利用对象/表情索引按明细精确聚合；热门对象计数耗时仍随该对象回应数量增长。后续若热点流量和响应时间要求需要，再迁移到独立汇总计数，不把计数塞进正文或通用 post_meta。

2026-10-15 验证：

- `pnpm typecheck`、`pnpm build` 通过。
- 安全测试 45 项通过，覆盖权限、来源、大小、请求白名单、重复/并发写入、表情切换、停用历史保留、私密分页、下架/整串隐藏与在途互动的锁协调、级联清理及共享限流。
- 维护测试 5 项通过，实际备份恢复包含四类互动记录及表情配置；原有 16 表旧备份仍可恢复到独立新目标。
- 模拟数据包括 529950 条内容表情、10 万条评论表情、内容/评论各 1 万收藏，以及原有 10 万内容/10 万评论。单个热门内容有 3 万表情。
