# 前台首页与公开路由

## 发帖与回复（2026-10-21）

- 文字帖子与回复复用原有 PostComposer 弹层和公共 Select、Textarea、Dialog、Toast；正文上限 5000 字，帖子须选择分区，最多 9 张图片。底部保留原来的 @、图片、视频、链接、引用图标与布局；图片按钮提供上传/媒体库菜单，其余入口保留 UI 和不可用语义，后续逐项补齐；正文的普通链接沿用 ContentBody 安全展示。
- `GET/POST /api/v1/account/publications` 提供登录后的分区选项与发布；`GET/PATCH /api/v1/account/publications/{post|comment}/{公开短 ID}` 提供本人内容读取、编辑和删除，入口只在详情页加载，不给信息流每条内容增加权限请求。文章发布仍使用现有后台流程。
- `034_member_publishing.sql` 追加按账号和请求 UUID 去重的发布记录及会员内容审计。Core 限制正文、媒体、来源、请求体和频率；数据库事务中重新确认未封禁的作者、分区、图片所有权、目标可见性及同帖回复关系。短 ID 与正文、媒体引用、动态、通知、审计同事务提交，失败整体回滚。
- 同一请求重试返回原结果；不同载荷复用请求 ID 返回冲突。编辑/删除必须携带当前 version。删除帖子使用 archived 保留管理记录，公开列表、详情、图片权限、动态、sitemap 随既有可见性查询撤销；删除评论清空正文，删除主评论时隐藏整串回复。通知可见性同步检查原帖作者和主评论状态。
- 发布成功关闭弹层并提供右上角提示及“查看”入口，留在当前页面；刷新服务端内容，同时使现有详情复用数据失效，避免旧正文、计数。失败保留输入，未提交内容关闭时确认放弃。不保存跨设备草稿，不预先插入虚假成功内容。
- 图片复用已接入的本人媒体库，可上传、多选、移除和拖拽排序（键盘左右方向键也可排序）。预览为小尺寸缩略图，自动换行、不设内部滚动条，末尾加号可追加图片。拖动经过固定布局位置时，邻图以共享 180ms 动效让位，松手平滑落位；中断时从当前可见位置继续，减少动效与键盘排序即时更新，不增加依赖。媒体库每页 50 张、最多 500 张；上传重复老图片直接按内部 ID 读取已有记录，不依赖首屏列表。公开帖子通过已有 `/api/site-media/` 读取实际引用图片，私人媒体入口和二维码权限不扩大。其他单选头像/二维码入口保持单选。
- 评论活动及回复通知复用现有数据库触发器，通知不会发送给自己。没有新增发帖种子奖励规则，勋章继续使用现有条件检查。
- 增加 member-publishing-cases 并纳入安全测试：登录/来源/请求大小、重复请求、作者越权、媒体归属、版本冲突、跨帖回复、隐藏评论、通知去重和删除后的公开可见性。尚未执行迁移、类型检查、构建、测试或浏览器验收；需运行 `pnpm db:migrate`、`pnpm typecheck`、`pnpm build`、`pnpm test:security`（专用测试数据库）。

## 个人图片与资料保存（2026-10-21）

- `/members/{id}/edit` 使用专用表单骨架：标题、头像与上传入口、昵称、简介、地区、联系方式及可见范围、底部操作区。占位复用编辑页的间距和响应式布局；实际表单同步标记可测量的骨架节点。通过现有 SiteTransition 的服务端 slot 选择，不新增加载边界或路由状态。

- 新增迁移 `033_member_media_profiles.sql`。个人媒体按账号持久存储，以原文件 SHA-256 在同账号内去重，使用持久的 10 位 Base36 地址；上传复用现有本地媒体存储、静态图片校验和 WebP 处理，不新增依赖。当前每人最多 500 张图片（每页 50 张），单张 5 MiB、2,000 万像素。
- `GET/POST /api/v1/account/media` 读取本人媒体库与上传；`GET /api/v1/account/media/{id}` 读取本人图片。`GET/PATCH /api/v1/account/profile/details` 读取与保存资料，校验来源、请求大小、媒体归属与资料版本，并在事务中记录审计。
- `/api/member-media/{id}` 只公开正在使用的头像；带 `contact=1` 时只返回已绑定的联系方式二维码，按 public/friends/hidden 判断，friends 要求双方互相关注，本人始终可见。所有新图片接口均 no-store/noindex，二维码不进入 sitemap 或 JSON-LD。
- 用户页服务端只传递当前访问者可见的联系方式；资料与媒体读取不设置共享缓存。资料保存成功后留在编辑页，使用共享 Toast 提示“个人资料已保存”，按钮显示“已保存”；再次修改后恢复可保存状态。保存响应更新当前版本，刷新服务端数据与顶栏头像但保留表单和滚动位置，返回个人中心由用户主动点击。公开用户页原有 H1、canonical、robots 和 ProfilePage 规则保留。地区文本可保存；城市自动反查及视频未接入。
- 本次仅修改源码并做静态核对，未执行迁移、构建、类型检查、测试或浏览器。请执行 `pnpm db:migrate`、`pnpm typecheck`、`pnpm build`、`pnpm test:security`（创建专用测试数据库）及 `pnpm test:public-site`；新增安全用例涵盖持久去重、跨账号引用、版本冲突、单向/互相关注与二维码权限撤回。

当前使用 Core 默认实现，Custom 源码保留但未装配。旧前台 `/content`、`/content/[id]`、Custom 捕获路由和比较页已移除；后台及 API 保留。

## 链接规范

现行地址（2026-10-20 源码现状，尚未构建或浏览器验收）：

| 用途 | 地址 | canonical / 索引 |
|---|---|---|
| 首页信息流 | `/`；文章 `/?feed=articles`；精选 `/featured` | 自身；`?after=` 分页 noindex,follow |
| 帖子 | `/threads/{id}` | 自身 canonical；演示/非索引环境 noindex |
| 文章 | `/p/{id}` | 同上 |
| 评论 | `/comments/{id}` | noindex,follow；canonical 指向 `/threads/{父 ID}` 或 `/p/{父 ID}`；不进 sitemap |
| 用户 | `/members/{id}` | 自身；演示 noindex |
| 社区 | `/community`；话题 `/community/{topic}`；帖子 `/threads/{id}`；排序 `?sort=hot|mine` | 默认最新自身；排序/分页 noindex |
| 后台与接口 | `/admin/*`、`/api/*` | 不进 sitemap |

公共约定：

- 公开 ID：10 位 Base36 且至少含一个字母、小写；大写 308 到小写；无效或类型不符返回 404；不暴露数据库 ID。
- 一个实体只有一个 canonical；开发阶段不保留旧路径兼容，需要时再单独评估跳转。
- 分页 `?after=`（加密封装）和排序 `?sort=` 只作为查询参数，不生成可索引的路径变体；分页 canonical 指向自身，分页与排序页 noindex,follow。
- 路径小写、连字符分词、不带结尾斜杠；集合栏目用复数（tools/guides/rankings/members），不可数或集合名词用单数（gear/community），分类与栏目保持同一数，详情只用资源 slug。
- 保留前缀：`admin`、`api`、`_next`、`content`、`featured`、`t`、`p`、`c`、`u`、`members`、`community`、`discussions`、`favicon.ico`、`robots.txt`、`sitemap.xml`；Custom 路由不能占用。

规划中（未实施）：

- 栏目 `/community`、`/tools`、`/guides`、`/gear`、`/rankings`，分类 `/{section}/{category}`，内容 `/{section}/{category}/{slug}`；社区帖子使用 `/threads/{id}`；`contents.slug` 预留给后续文章/语义路径。
- 分页继续使用加密游标，不做数字分页。

## 页面

- `/`：推荐（默认）；`/?feed=latest`：推荐的兼容入口，canonical 指向 `/`；`/featured`：社区精选；旧 `/?feed=featured` 通过 Next permanentRedirect 跳转并保留 after 分页参数；`/?feed=articles`：文章。
- `/community/{topic}`：话题归档；`/threads/{id}`：帖子详情，由根 `@detail` 拦截槽承载、与列表同级，软导航保留列表；正文优先复用列表已注册数据，评论独立异步；`/p/[id]`：文章；`/members/[id]`：用户公开资料，不设自定义 handle。作者链接、ProfilePage 的 canonical 与 `Person` URL 统一使用 `/members/`。
- 首页每页最多 20 条，每条最多读取 1500 字符，并返回是否截断。正文按实测行数折叠：小屏超过 5 行保留约 4 行，40rem 起超过 7 行保留约 6 行；段间距仍按真实位置保留。完整正文可原地展开/收起，超过读取上限则链接进入详情。卡片加载本地头像与最多九张配图缩略图。下一页使用绑定视图的加密游标。
- 首页与 `/featured` 复用 FeedPage 服务端列表和 metadata，精选分页使用 `/featured?after=…`，canonical 与站内链接一致；站点允许索引时 sitemap 包含 `/featured`。精选页保持页面级 30 秒原生路由缓存，并通过 `@detail/featured/page.tsx` 在离开拦截详情时清空槽。`featured` 同时作为宿主保留路径，Custom 不可覆盖。
- 服务端渲染内容，Next Link 无刷新导航；菜单、信息弹窗及局部骨架过渡为客户端交互。详情链接使用 Next 默认预取，在路由 loading 边界停止；用户资料和列表分页仍关闭预取以限制请求。
- 菜单与信息弹窗使用公共 shadcn/Radix 组件，保留点击外部/Escape 关闭、焦点约束和触发器焦点返回。基础组件随页面加载；信息弹窗按当前要求留空、水平居中且靠近顶部。触发图标的动画状态和高亮持续到弹层退出完成。
- 详情页提供正文、本地配图和只读的嵌套评论列表；列表表情、点赞和收藏已接入后台；前台发布与评论写入尚未接入。独立页面对不存在的、类型错误的、未发布的内容以及封禁作者返回 404；列表中已打开的详情层收到失效结果后隐藏旧正文并提示内容不可用。
- 信息流顶部提供“推荐 / 精选 / 朋友圈”：推荐沿用 latest、精选沿用首页 featured，朋友圈保留禁用语义，不展示开发阶段提示，不以其他数据冒充关注信息流。列表顶部发布区已移除，分类菜单下直接显示帖子。菜单由全局 Header 中间区域承载，与详情页的返回/发帖工具栏按页面配置切换；线条与无圆角规范见 DESIGN.md；继续使用整页滚动，不创建内部滚动容器或滚动监听。侧栏原有文章入口保留。尚未完成浏览器验收。

### 帖子与文章详情

帖子与文章的独立/拦截详情均启用页面级 `unstable_dynamicStaleTime=30`，与首页保持同样的有界原生路由缓存。短期重访可复用已返回的评论片段，评论骨架只在实际等待时出现，不因访问动作必播。缓存失效、过期或主动刷新仍重新读取；不添加客户端评论缓存、永久访问名单或服务端共享数据缓存。缓存窗口内可能暂时显示上一份公开内容/评论，重新读取时仍由 Core 校验可见性。

首页菜单由公共布局中的 FeedFrame 渲染，独立于异步页面与帖子读取。分类和分页变化保留页面外壳，只有帖子及分页区域使用局部 Suspense/骨架；从刷新后的详情首次返回首页也立即展示菜单，只有首次文档访问复用公共 SSR Splash。菜单仅更新当前选中项，不随列表重新出现；不增加浏览器滚动控制或业务数据缓存。入口契约见 docs/SKELETON.md。

- `(site)/@detail/(.)t/[id]` 与 `(.)p/[id]` 拦截站内详情导航；默认、首页和 catch-all 槽返回空，刷新或直接访问走原有独立详情页。不是原生 View Transition，也不自行操作 history。

### 帖子链接轮播（2026-10-22）

发帖与编辑弹窗的链接工具支持粘贴公开 HTTP/HTTPS 网址，自动读取标题、图标和分享封面，允许修改标题、从自己的图片库选择封面；图片、视频、链接合计最多 9 项，共用排序与删除。链接详情弹窗保持常规加载，链接卡片服务端输出真实外链并复用站外确认，不进入图片灯箱；JSON-LD 图片列表不混入网页 URL。

Core 的 `/api/v1/account/link-preview` 为鉴权 POST 接口，检查来源与请求大小。先使用进程内有界缓存（最多 500 项，成功 24 小时、失败 5 分钟），再直接抓取；标题或分享图缺失时向 Microlink 免费接口补充。Microlink 不需密钥或 SDK，已有数据库限流在实例间限制备用调用至每 24 小时窗口最多 25 次；供应商自身额度和反爬限制仍可能导致失败，失败保留已取得的字段并允许手工补充。仅保存用户确认的卡片快照，公开浏览不抓取目标网页。缓存重启失效，进程内合并同网址请求；跨实例不共享缓存。

抓取仅允许普通公开域名和默认 HTTP/HTTPS 端口，每跳校验 DNS 并固定连接地址，拒绝内网/保留地址、凭据与非网页协议；直接抓取超时 6 秒、最多 4 跳、HTML 上限 512 KiB，备用请求 10 秒、JSON 上限 64 KiB。复用现有 xmldom 0.9.12 解析有界 HTML，不执行目标脚本。远程封面/icon 保留远程地址（不保证防盗链资源可用），不发送 Referer；加载失败显示默认图形或省略图标。自选封面沿用媒体所有权、引用删除保护和帖子公开性检查。

追加迁移 `036_content_links.sql` 保存卡片顺序和封面引用，与发布/编辑的 revision 检查、事务审计同步提交；上线前先运行 `pnpm db:migrate`。这次未执行迁移、构建、类型检查、测试、浏览器或真实外站抓取验收。已补充安全与混排回归用例，由维护者执行 `pnpm test:security`（创建专用测试数据库），并检查普通站点、抓取受阻站点、额度耗尽、手工封面、混排后重开编辑及公开/归档的封面可见性。

## 我的 SOHO 圈

`/circle` 是登录用户的个性化帖子列表，包含本人及其单向关注对象发布、评论、点赞或点表情的帖子；对可见评论/回复的表情也归入所属帖子。收藏、仅关注我的人不构成入选依据。多种互动和多人参与仍只展示一帖。

Core 的 `getSiteCircleFeed` 从会话确定用户，数据库 `readSiteCircleFeed` 直接查询当前业务记录，使用 EXISTS 在分页前判断参与关系，不依赖历史动态表。撤销最后一项有效参与、取消关注、隐藏内容或封禁账号会在下一次服务端读取时改变结果；其他仍有效的入选依据继续保留。评论及所属根评论、作者均须满足当前可见条件。

列表按帖子发布时间与内部 ID 倒序，旧帖的新互动不会改变位置；内部 ID 仅用于查询及加密游标，对外帖子仍使用持久化的 10 位公开 ID。每页展示 20 条，多取一条判断下一页；游标绑定圈子视图和当前账号。沿用批量媒体/作者展示、服务端卡片与原生导航，不增加客户端列表缓存。个人圈子不进入 sitemap，不输出聚合 JSON-LD，metadata 为 noindex,follow，自有 canonical。页面设置动态导航过期时间为 0；浏览器返回保留行为仍遵循 Next 原生机制。

追加迁移 `038_circle_feed.sql` 提供公开帖子时间游标索引与有效评论的帖子查找索引。`pnpm test:public-site` 中包含圈子筛选、单向关系、撤销/隐藏、封禁及同时间戳分页用例；新增用例尚未运行。实际性能需要用真实数据检查查询计划，索引不代表固定扫描量或响应时间保证。
