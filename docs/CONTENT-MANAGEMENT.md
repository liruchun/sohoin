# 内容、分类与标签

## 已实现

- `/admin/content`：标题前缀搜索、类型/状态筛选、主键游标分页；点击分类或标签可筛选关联内容。列表最多读 31 条、展示 30 条，不读取正文。
- `/admin/content/new`、`/admin/content/{id}`：标题（最多160 字符，帖子选填）、摘要（500）、纯文本正文（50,000）、类型、一个主分类、最多十个标签；编辑器中的分类/标签可前缀搜索、分页，不一次读取所有数据。
- `/admin/taxonomies/categories`、`/admin/taxonomies/tags`：新增、修改、删除、名称前缀搜索和分页。名称可使用中文；同类 slug 唯一，使用小写字母、数字、连字符。当前为平级分类，不含层级与拖拽排序。
- 草稿默认不公开；发布须有标题、主分类和正文。已发布内容保存会立即更新前台；草稿/下架不提供公开预览；管理员可通过 /admin/content/{id}/preview 查看最后保存版本。永久删除仅允许草稿或已下架内容，前端明确确认；不含回收站。
- 被任何内容引用的分类/标签不可直接删除，包括草稿引用；先编辑相关内容解除关联。更新采用 version 冲突保护，返回 409，不自动覆盖。
- 内容、分类和标签写入在事务中重新检查管理员权限。用户权限行使用共享锁，角色调整的行锁必须等待相关写入完成；没有用全站锁串行化所有内容写入。正文和标签关联、精简审计同事务提交。
- `/admin/audit?type=content` 查看内容、分类、标签的成功新增/更新/删除。日志保留对象标题/名称与操作人，不复制完整正文，避免重复存储大文本。

## 前台与性能

首页读取最多六篇已发布内容，没有已发布内容时保留原有演示。`/content` 提供已发布内容列表，`/content/{id}` 提供详情。分类及标签名称为纯文本，不自动生成独立分类页、标签页、话题页，也不写入站点导航设置。列表 API 可按 categoryId、tagId、type 筛选。

公开接口只返回已发布数据，草稿、下架或已删除详情均 404。正文由 React 作为纯文本转义、保留换行，不解析 Markdown、不接受 HTML 执行；不包含用户内容审核或富文本净化器。前台为服务端输出，不加载后台编辑组件和后台 CSS。详情自己的 CSS 仅在 content 路由加载。

数据库使用参数化 SQL、前缀搜索索引、状态/分类/类型游标索引与标签反向索引。列表只使用一个有上限的查询，关联标签在查询中通过索引聚合；不从应用逐行查标签，不读正文或扫描总数。排序按内容编号倒序，不承诺按最近发布时间排序；每次查询读取当前已提交数据，分页不是固定快照。

## Core / Custom

当前内置 `article`（普通文章）与 `post`（社区帖子）。类型共用公共字段，并可声明经过校验和公开范围控制的扁平扩展字段，不开放任意 JSON。扩展契约在 `packages/extension-api`，数据 Schema 在 `packages/extension-api/content`。

在 Custom 的 `registerCustom()` 返回值中添加可信源码注册：

```tsx
contentTypes: [
  { id: "short-note", label: "短帖", Template: CustomNoteTemplate },
]
```

`Template` 是接收 `{content: PublicContent}` 的 React 组件，可省略以使用 Core 默认纯文本模板。host 将 Custom 声明传给 `createContentService`，Core 不导入 Custom。编辑器及 APP 从 `/api/v1/content-types` 获取 id/label，不返回组件。相同 `article` id 可以定制标签和模板；重复的 Custom id 或非法声明会被拒绝。数据库中原有类型若撤销注册，仍可读取并使用安全的默认模板；再次保存须选择已注册类型。

新增内容类型无需新增分类/标签表；少量字段可通过 extension 声明注册，频繁检索的数据使用明确列或专属表。专属字段编辑组件仍需按具体需求接入。Core 升级不覆盖 Custom。

## HTTP 与安全

- 公开：`GET /api/v1/content-types`、`GET /api/v1/content`、`GET /api/v1/content/{id}`。
- 管理员：`GET/POST /api/v1/admin/content`、`GET/PATCH/DELETE /api/v1/admin/content/{id}`。
- 管理员：`GET/POST /api/v1/admin/taxonomies/{kind}`、`GET/PATCH/DELETE /api/v1/admin/taxonomies/{kind}/{id}`，kind 仅为 categories/tags。
- 管理员审计：`GET /api/v1/admin/audit/content`。
- 新建内容提交 ContentValue；更新提交 `{version,value}`；删除提交 `{version}`。正文不是 PATCH 任意字段合并；契约均为严格允许列表。分类标签更新采用相同版本包装。
- 新建/更新正文 JSON 上限 256 KiB，其他写入 4 KiB；HTTP 适配器校验来源，Cookie 与无 Cookie 的 Bearer APP 共用同一 Core 服务。管理读取每位管理员限 120 次/分钟，内容及分类标签写入共用 30 次/分钟额度。公共读取不使用全站共享计数器限流。
- 所有内容接口 no-store，更新和下架后下一次公开请求立即反映状态。网站读取直接调用服务，APP 使用 HTTP 适配，不维护另一套业务规则。API 已加入 OpenAPI。

新增迁移 `005_content.sql`；不修改已应用迁移，不新增项目依赖。

## 管理员预览与组合筛选

2026-10-15 用户确认暂时保留纯文本正文，不接入编辑器依赖。

列表提供分类/标签选择器，可与标题前缀、类型和状态组合；查询会重置分页，分页与表格中的分类/标签快捷链接会保留其他筛选。选择器展开时才请求候选项，每页最多 30 条；已选名称通过主键点查询恢复，不预加载全部分类标签。选择器不嵌在 GET 表单中，实际提交只包含标准查询字段，避免单选框名称混入严格契约。移除条件后应用即可清除对应条件。

编辑页和列表的预览入口打开 /admin/content/{id}/preview；只对管理员开放，逐次调用带鉴权的共享 Core get，不使用公开内容接口，也不生成公开分享令牌。响应 no-store，页面 noindex/nofollow，使用与前台相同的已注册正文模板；只显示最后保存的内容，不包含本地未保存修改。给模板传入公开详情结构，不额外传入管理版本等字段。预览只展示正文模板，不复制整个前台页面框架。

新建内容须先保存再预览。草稿及下架内容的公开 API/详情仍返回404，预览不改变状态，不执行 HTML。新增 GET taxonomy detail 仍仅允许管理员，并加入 OpenAPI。无新增迁移或依赖。

## 后台媒体关联

内容表单可选择 1 张封面、10 张图库图片、10 个图片附件；按每处使用编辑替代文本和说明，图库/附件可上下调整顺序。媒体库展开时才请求候选项。所有修改与正文一起保存，共用内容 version 与审计事务，离开未保存表单时沿用现有提醒。

旧客户端省略 media 字段时保留已有关系；显式空数组清空；非空数组完整替换。服务端只接受 ready 图片，并与媒体删除使用相同行锁。前台和正文预览暂不展示图片，不向公开接口增加私有媒体字段。
