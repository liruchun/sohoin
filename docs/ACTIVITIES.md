# 关注动态流基础

已应用追加迁移 `014_user_activities.sql`。提供统一活动记录、Core 服务 `getFollowingActivities`、`packages/extension-api/activities` 契约及 GET `/api/v1/account/activities`。暂不实现前台页面，不新增依赖、缓存服务、消息队列或向粉丝复制动态。

## 活动来源与一致性

活动种类：

- `content_published`：文章、帖子或其他注册内容类型的首次发布，行为人是内容作者。
- `comment_created`：发表评论或回复，通过 comment.reply_to_id 区分具体回复关系。
- `content_reacted`：内容上的表情回应，包括点赞。
- `comment_reacted`：评论上的表情回应。

收藏保持私密，关注关系本身也不生成本版活动。没有开放手动提交活动的接口。

数据库触发器随来源写入自动记录活动，和业务修改处于同一事务。业务失败或事务回滚不会留下活动；未来评论发布服务写入现有评论表时也会自动记录，不能再额外手工重复插入活动。

表中只保存行为人、类型、所属内容、可选评论关联、有效标记、首次活动时间及编号，不复制正文、用户身份资料、媒体文件地址等数据。内容、评论、用户使用外键关联，实际删除时清理相应活动。

同一用户、行为类型和目标只保留一条活动。编辑已发布内容、下架后重新发布不会生成第二条发布活动。切换表情更新来源记录，动态读取当前表情；取消表情使活动失效，重新回应复用原活动编号和时间，不顶到最新位置。停用表情种类不抹除历史回应。

## 读取与可见性

接口只读取当前登录账号目前关注的用户，包含关注前已经存在的可见活动。取消关注后立即排除对方历史活动，重新关注后恢复查询。禁用的行为人不展示。

所属内容必须当前已发布。涉及评论的活动还要求评论正常、整串未隐藏；单独隐藏一级评论不连带隐藏其正常二级回复，一级正文删除也不强制隐藏仍有效的二级回复。已隐藏或删除的评论正文不复制到动态表，查询时也不返回。

查询同时检查当前反应记录是否存在、发布/评论行为人是否仍与来源一致。可见性和关注关系在数据库查询中先筛选，再按活动编号倒序读取 31 条，最多返回 30 条，以判定下一页；不先截取一批再在应用层过滤，不会因为最新活动被隐藏就错误结束分页。

使用 `?before=nextCursor` 查询更早活动。列表只含用户编号/最多 100 字符的名称、内容编号/类型/标题/最多 280 字符摘要、可选评论编号/最多 120 字符预览/回复对象编号、可选表情编码/标签/字符和首次活动时间，不加载全文、不逐条请求用户或正文、不查询动态总数。

接口须登录，Core 执行身份校验和共享限流；请求参数严格限定为 before，不能指定另一个账号作为动态流主人。响应 no-store，OpenAPI 已同步。当前按活动编号排序；不是跨请求数据库快照，刷新可获取后来提交的活动。分页期间新发生的关注、可见性和内容变化按每次读取时的状态生效。

## 升级与维护

迁移会根据已有发布记录、未删除评论及当前表情记录补入可恢复的历史活动，按来源时间排序生成编号。已经取消的历史表情、删除前的评论等无法从现有表还原，不伪造这部分历史。迁移期间锁定相关来源表的写入，以保证历史补入和触发器安装之间没有遗漏窗口；大规模已有数据升级应安排维护窗口。

活动已纳入备份和恢复计数，旧备份仍按原有清单兼容恢复。数据库检查追加表情活动有效标记与真实表情记录的一致性检查。

## 验证与后续边界

`pnpm typecheck`、`pnpm build`、60 项安全测试和 6 项维护测试通过。覆盖首次发布/重复编辑、回复关联、两类表情活动、取消再点赞不刷屏、私密收藏不外泄、事务回滚、当前关注和禁用状态、单条/整串隐藏、评论删除、隐藏活动占据最新区间时的正确分页及来源级联清理。

独立升级数据库验证旧表到 014 的历史补入，确认原时间保留、重新发布不重复、收藏不进入活动，且表情取消/重加仍保留原编号。实际 pg_dump/pg_restore 验证活动与来源关系一并恢复；旧 16 表备份也已实际恢复到独立新目标。

`pnpm test:activities` 在隔离数据库中验证关注 1 万人、四类活动来源、连续 50 页及最新 5000 条活动隐藏的情况，报告 `.local/performance/following-activities.json`。仅作为本地基础方案检查，不代表生产并发容量。

本次模拟包含 3 万用户、10 万内容、10 万评论、20 万表情记录，触发器生成 37 万活动，另追加 5000 条隐藏评论活动。数据库查询 P95：首页 10.25ms、连续 50 页后 9.70ms、评论区间 9.54ms、发布区间 9.13ms；最新 5000 条隐藏时 24.59ms。含登录校验的 HTTP 测试在隐藏区间场景下 P95 为 42.76ms，较深页为 18.81ms。此数据只说明该测试分布下结果正确且开销可观察，不证明所有数据分布或并发量下都相同。

公开页面资源测量 `.local/performance/activities-after.json`：首页 JS 8 个/570454 字节、CSS 1 个/4848 字节，与本次改动前相同，公共客户端未引入后台模块。

后续才考虑回复合并、活动类型筛选、未读提醒、动态保留周期、热点缓存和动态收件箱。活动读取保留在同一个 Core 服务后面，按实际数据量和响应时间扩展；本版不承诺大规模并发下的固定延迟。
