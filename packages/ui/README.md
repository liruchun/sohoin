# Public UI

Public primitives adapted from shadcn/ui through existing Radix, CVA and cn dependencies. Import individual entrypoints; do not import admin-ui or its providers/styles here.

- `button`: Button and CVA variants for appearance and size.
- `textarea`: Native shadcn-style Textarea with shared public styling and standard textarea props/ref; no mention or editor behavior.
- `animated-number`: `<AnimatedNumber value={count} />` animates confirmed numeric changes with a 260ms vertical roll/fade (increase upward, decrease downward). Optional `hideZero` hides zero after the outgoing number finishes; `format` accepts a formatter in client components. First render is static; reduced motion switches immediately. Uses native CSS with at most two text nodes, no dependency, timer, observer or live-region announcements. Import from `@sohoin/ui/animated-number`; inherit typography/color or pass `className`. Set `--animated-number-height` to align the centered number viewport with adjacent icons (defaults to `1.25em`).
- `icon-button`: IconButton with `animation="menu" | "rotate" | "none"` and `active`. Active controls the icon state and foreground without a hover background. The consumer owns open/close state; keep active until the overlay finishes exiting.
- `dialog` / `dialog-content`: Radix root/trigger and shared content, title, description and close control. Content defaults to a top-aligned position, supports default/large sizes and handles viewport bounds. Use `size="document"` only with a non-modal root for route details that belong in document flow: it renders inline without a portal/overlay, fixed positioning, height cap or nested scroll viewport. It retains Radix dismissal/focus lifecycle and the page entry/exit animation; the host keeps global navigation and the document scrollbar outside it. Ordinary dialogs and image lightboxes retain their existing behavior.
- `dropdown-menu` / `dropdown-menu-content`: Radix root/trigger, content and item. Preserve keyboard navigation and dismissal.
- `utils`: pure cn helper, with no interactive imports.
- `relative-time`: Server-rendered `RelativeTime` displays Chinese relative time for the last/next seven days and calendar dates beyond that, including the year when different in Asia/Shanghai. It retains an ISO `datetime` and full Beijing timestamp in `title`/accessible text. No client timer; labels update on a fresh server render. Import the individual entrypoint from server components. Boundary regressions: `node --import=tsx --test packages/ui/tests/relative-time.test.ts` (not run for this change).
- `skeleton-reveal`: SkeletonBoundary, SkeletonFallback and SkeletonContent for a real Suspense wait followed by bounded geometry-based reveal. No data fetching or extra dependencies.
- `page-scrollbar`: Legacy optional document-scrollbar overlay export, retained for compatibility. The public host no longer mounts it or hides native scrollbars: it uses a CSS-styled native document scrollbar from the initial render onward, avoiding the native-to-custom hydration handoff. Do not reintroduce this component into the public layout.

Tailwind classes and CVA variants live in each component. Only complex icon/mount/exit motion and viewport variables live in adjacent CSS Modules. The host imports `theme.css` after Tailwind's theme/utilities and explicitly scans this package's `src` files with `@source`. It does not need a client provider, per-instance style injection or a global component stylesheet. The current host omits Preflight to preserve existing admin/Custom behavior.

Keep classes statically discoverable; do not construct utility names from fragments. Follow root DESIGN.md for rem-based sizes, colors, reduced motion and client/server boundaries. This refactor has not been built, tested or inspected in a browser; validation is performed by the user.

## Measured skeletons

The fixed integration and motion contract is [docs/SKELETON.md](../../../docs/SKELETON.md). Update it and the regression cases whenever changing the workflow; ordinary card/media/text changes only supply geometry markers.

`SkeletonBoundary` tracks a committed fallback synchronously. `SkeletonContent` retains the wait until completion, including its measured start time. Named body/discussion records live in the route layout across loading-to-Page replacement; query changes replace a record, not cache another cursor. SSR parser bootstrap identifies document entry; SPA innerHTML scripts remain inert. Cached/immediate SPA content bypasses measurements and timers. The host keeps Next's existing page-scoped 30-second native Router Cache and scroll restoration; no KeepAlive, business cache or visited-page list.

For the public host, pass Splash once to `SkeletonBoundary splash={…}` outside Suspense. Both fallback and resolved content share this persistent cover; they must not mount separate SVGs. CSS starts its one-shot animation during parsing and hydration never seeks or rewrites its animation timing. The cover stays display:block for the document entry, using visibility to hide after fading, so Strict Mode cleanup/replay cannot restart its SVG. Parser scripts live in `skeleton-bootstrap.ts`; the content hydration-failure timeout also hides the persistent cover. VM regressions cover shared timestamps and recovery, not actual React/browser mounting. Legacy per-slot splash props remain supported for other consumers.

Responsibilities are separate: `skeleton-contract` owns entry eligibility, legal phases, row timing and limits; `skeleton-sequence` exclusively advances normal phases and waits for completion barriers; `skeleton-clock` owns cancellable deadlines/paint frames; `skeleton-runtime` adapts lifecycle and recovery; `skeleton-layout`, `skeleton-geometry` and `skeleton-morph` prepare paused animations and real shapes. Existing public component APIs and server-rendered content remain unchanged. Timing is read at the common root, never from individual card styles.

SSR retains its 512ms measured-skeleton minimum overlapping entrance. Async SPA reveals immediately after geometry and one final paint barrier, without a measured-skeleton minimum hold. Both use the same sequence controller. SSR retains the 860ms Splash minimum, full 400ms exit and 512ms entrance. SPA retains two placeholders, 320ms morph/expansion and 20ms geometry stagger. Both crossfade skeleton/content for 280ms with an independent 80ms row stagger. Complete immediate data bypasses the sequence. The old settle timer is removed.

The host uses one public navigation animation, including feed routes, query pagination and profile links. Detail layouts retain body data and body/discussion waits across loading-to-Page replacement; full detail DOM stays inside Page for native scrolling. Truncated data waits for the full body; complete data displays immediately. No new page cache, history or scroll manager is introduced.

Opt a server-rendered region into first-response reveal with `SkeletonContent revealToken={{}}`. Create that object in the Server Component response, never on each client render. A fresh token reveals even if no fallback committed; the same cached token bypasses after completion. The top SkeletonBoundary shares a WeakSet of completed response identities with its descendants; it stores no content, URL, expiry timer, or strong reference to a response. New responses after cache invalidation get new tokens. Interrupted reveals are not marked complete. The public host currently opts in only intercepted discussion regions; document entry remains unchanged.

Semantic markers and bounds remain described in [docs/SKELETON.md](../../../docs/SKELETON.md). Placeholder and measured text bands share --site-skeleton-text-height (.8125rem), vertically centered on measured lines. Ordinary input/focus cannot skip the sequence. Layout invalidation refreshes final geometry before reveal instead of exposing content early. Reduced motion, hidden documents, unsupported animations, errors and unmount retain recovery and cleanup. Hydration failure restores content after 8000ms.

`pnpm test:skeleton` contains pure Node regressions for eligibility, legal phases, completion barriers, interruption, SSR, empty animation groups, failures and semantic shape mapping. No database, server or browser is needed. Tests, typecheck, build, browser and production payload checks have NOT been run in this revision; the user should execute them under project rules. Phase tests do not verify browser geometry or guarantee visual/performance acceptance.

## Carousel

### Image lightbox

`@sohoin/ui/image-lightbox` exports `ImageLightbox` and the `LightboxImage` type (`src`, `alt`, `width`, `height`). Pass server-rendered image links as children, with `data-lightbox-index` matching the image array. The wrapper enhances normal clicks only, preserving hrefs, modified clicks and Embla's drag-click suppression. Keep the gallery bounded by the host's existing media limits.

It composes the existing Dialog and Carousel without dependencies, with arrow keys/swiping, current position, full-image fit, loading/error text, original-image links, Escape/backdrop closing and trigger focus restoration. Imports are static; image elements for current, two neighboring and actually visible originals only mount inside the open dialog. `DialogContent` adds a `lightbox` size and `overlayClassName`; other dialog variants retain their behavior. No zoom/pan engine is included. Browser behavior, accessibility and build checks remain user-run.

### Reusable magnetic feedback

Small floating magnetic controls share the same hover treatment: the shared Button supplies a pointer cursor, and MagneticSurface transitions its visual border radius from .625rem to 1.25rem on fine-pointer hover using the existing 140ms feedback tokens. Disabled controls do not receive the treatment; reduced motion removes the transition. Keep this styling on the surface instead of overriding its radius in each consumer. This rule does not apply the shape change to ordinary form buttons or header IconButtons.

`@sohoin/ui/magnetic-surface` exports `MagneticSurface`. Place it directly inside a fixed Button or link and put that control's visual background, border and contents on the surface. Keep the parent's hit area and focus outline stationary. The surface owns its inline transform; use another nested layer for any additional transforms. A `data-magnetic-area` ancestor optionally tracks the pointer outside the control; without it, tracking is limited to the parent. Do not place interactive descendants inside the surface. Set `disabled` whenever the control is unavailable.

Options: `radius` (default 112 CSS pixels), `maxOffset` (default 10 CSS pixels), and `disabled`. Following uses a 0.3 distance multiplier with smooth radial falloff; actual displacement stays below the configured cap. Pointer events are coalesced to one pending animation frame; only the fixed parent is measured, with no React updates or continuous animation loop. The surface uses the existing 140ms feedback transition and easing. Touch, reduced motion, dragging and keyboard input reset/disable magnetic movement. Listeners and pending frames are cleaned up on disable/unmount.

CarouselPrevious/CarouselNext accept the opt-in `magnetic` prop. The public content carousel enables it and marks its root `data-magnetic-area`; group navigation, hidden unavailable controls and the fixed click target remain unchanged. Typecheck, build and browser feel checks have not been run.

`@sohoin/ui/carousel` provides the shadcn-style `Carousel`, `CarouselContent`, `CarouselItem`, `CarouselPrevious`, `CarouselNext` and `CarouselStatus` composition on user-approved `embla-carousel-react@8.6.0`. It reuses the shared Button, has no autoplay/plugin dependency, and defaults to start alignment without looping. The host supplies an accessible name and slide labels; static server-rendered slides may be passed as children. It supports mouse/touch dragging, arrow keys, focus-driven scrolling, disabled end buttons and live position text. Hosts can set `opts.slidesToScroll` to `"auto"` for viewport-sized groups and pass `grouped` to `CarouselStatus` to announce group position alongside the image total. Reduced-motion button navigation jumps immediately. Vertical panning and pinch zoom remain available. Before initialization, the viewport retains native horizontal overflow and enhancement buttons are hidden. Import it statically on routes that need it; do not defer loading until a drag or click. Browser/device and production-resource verification are pending.

No extra skeleton pulse loop/hold was added. Tests/build/browser remain unrun; see docs/SKELETON.md.

Initial shape morph and downstream expansion run together; actual content still waits for the shared completion barrier. This is user-directed choreography, not a claim of identical Bonjour timing. No browser/build/tests run.
